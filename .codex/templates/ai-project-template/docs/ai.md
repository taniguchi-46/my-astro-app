# AI 共通ガイド

このドキュメントは、複数の AI Agent が共通で参照するための行動原則です。

プロジェクト固有の現在状態は `status.md` を参照してください。Agent 固有の設定や振る舞いは、それぞれの専用ディレクトリに記載します。

## 参照方針

1. まず `README.md` でプロジェクト概要を確認する。
2. AI 共通ルールは `docs/ai.md` を参照する。
3. 現在の作業状態は `docs/status.md` を参照する。
4. 作業フローは `docs/loop.md` を参照する。
5. 設計判断が必要な場合は `docs/architecture.md` を参照する。
6. 命名や実装方針が必要な場合は `docs/conventions.md` を参照する。
7. 必要な場合のみ `docs/skills/` 配下の関連ファイルを参照する。

## 基本原則

- 既存コード、既存設計、既存の命名規則を優先する。
- 変更は小さく分割し、影響範囲を明確にする。
- 不要なリファクタリングや unrelated な変更を避ける。
- 不明点は推測で実装せず、確認または TODO として分離する。
- 重複実装を避け、類似コードを探してから実装する。
- AI 固有の設定は各 Agent 用ディレクトリに置き、共通知識は `docs/` に置く。

## 実装前チェック

- 依頼内容と完了条件を確認する。
- 関連ファイルと類似実装を検索する。
- 既存の設計、命名、ディレクトリ構成を確認する。
- 必要な依存関係や実行コマンドを確認する。
- 変更対象外のユーザー変更を巻き戻さない。

## 実装中チェック

- 小さな差分で進める。
- 各ファイルの既存スタイルに合わせる。
- エラー処理、空状態、レスポンシブ表示などの影響を確認する。
- 既存ファイルを移動した場合は、相対リンクや import を更新する。
- 不要な削除をしない。

## 実装後チェック

- 可能な範囲でテスト、ビルド、静的チェックを実行する。
- 差分をセルフレビューする。
- ドキュメント更新が必要な場合は `docs/` を更新する。
- 作成、移動、更新したファイルを報告する。
- 実行できなかった確認がある場合は理由を報告する。

## ドキュメント分離ルール

| 種類 | 配置 | 内容 |
|------|------|------|
| AI 共通ルール | `docs/ai.md` | Agent 共通の行動原則 |
| 現在状態 | `docs/status.md` | 作業状況、完了事項、保留事項 |
| 作業フロー | `docs/loop.md` | Analyze から Complete までの流れ |
| 設計情報 | `docs/architecture.md` | アーキテクチャ、API、状態管理など |
| 実装規約 | `docs/conventions.md` | 命名、ファイル名、import 順など |
| 用語 | `docs/glossary.md` | プロジェクト内の用語 |
| Agent 固有設定 | `.codex/` など | 各 AI Agent 固有の設定 |

## status.md の更新ルール

- 作業開始時に現在状態を確認する。
- 作業完了時や保留事項が発生したときに更新を検討する。
- 完了済みの履歴は不要に削除しない。
- 事実と未確認事項を分けて記載する。
