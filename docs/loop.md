# AI 作業フロー

このリポジトリで AI Agent が作業するときの基本フローです。

## 1. Analyze

- 依頼内容、完了条件、変更範囲を確認する。
- `docs/status.md` で既知の状態と保留事項を確認する。
- 影響しそうなページ、コンポーネント、記事、設定ファイルを洗い出す。

## 2. Search

- `rg` または `rg --files` で関連ファイルを探す。
- 似た実装や既存コンポーネントを先に確認する。
- Markdown 記事を変更する場合は `src/content.config.ts` の schema を確認する。

## 3. Plan

- 変更対象ファイルと確認方法を短く整理する。
- UI 変更ではレスポンシブ表示とナビゲーションの確認を含める。
- docs やテンプレートの更新が必要か判断する。

## 4. Implement

- 既存の設計、命名、スタイルに合わせて小さく変更する。
- 不要な抽象化を増やさない。
- 文字化けした文言を修正するときは、意味を推測しすぎず現在の機能に合わせて書き直す。

## 5. Test

- 可能なら `npm run build` を実行する。
- UI 変更ではローカル表示、リンク、ページネーション、記事詳細を確認する。
- Docker 関連を変更した場合は compose の起動確認を検討する。

## 6. Review

- 差分を見直し、依頼範囲外の変更が混ざっていないか確認する。
- Markdown の相対リンク、frontmatter、import パスを確認する。
- テンプレートとプロジェクト固有 docs が混ざっていないか確認する。

## 7. Complete

- 変更内容、確認結果、未確認事項を報告する。
- 残タスクが増えた場合は `docs/status.md` に反映する。
